# sales_os/linkedin — LinkedIn engage-first pipeline backend

Ports the former local `tools/outreach-tracker` LinkedIn pipeline (linkedin-playbook §14; the local app was removed 2026-06-17) to Supabase. Tier A/B/C prospects move through the engage-first stages with the locked cadence. UI is the **"LinkedIn Outreach" tab inside `/crm`** (scoped IIFE in [`../web/templates/crm.html`](../web/templates/crm.html)); API in [`../web/linkedin_routes.py`](../web/linkedin_routes.py) under `/crm/api/li/*`.

## Files

| File | What it is |
|------|-----------|
| `schema.sql` | `li_prospects` (name, linkedin_url, tier A/B/C, stage, replied, next_action_date, notes). Partial unique index on linkedin_url. **Run once in Supabase Studio.** |
| `supabase_writer.py` | PostgREST CRUD (list/create/update/delete), writable-column allowlist, secret key server-side. |

## Stages + cadence (offset = days until that stage's action is due; from §14 DUE constants)

`commented` (connect due +2) → `connect_sent` (passive, mark accepted) → `accepted` (first msg, +0) → `first_msg` (loom, +3) → `loom_sent` (stay visible, +7) → `engaged` (re-approach, +30) → `in_convo` → `won` / `dead`. The front-end recomputes `next_action_date` whenever the stage changes; "needs attention today" = active stage with `next_action_date <= today`.

## What does NOT go here

- HTTP API → `../web/linkedin_routes.py`; the page/markup/JS is the LinkedIn tab in `../web/templates/crm.html`
- KPI counters for LinkedIn actions live in the KPI tab (`kpi_daily`), not here
- Lead PII stays in Supabase only; behind the same Traefik basic auth as `/crm`
