# sales_os/crm — CRM + KPI backend

Persistence layer for the **`/crm` dashboard** (sidebar: Leads CRM + KPI Tracker). Replaces the local-only `tools/outreach-tracker/index.html` (browser localStorage) with a Supabase-backed, deployed, multi-device version. Front-end + routes live in [`../web/crm_routes.py`](../web/crm_routes.py) and [`../web/templates/crm.html`](../web/templates/crm.html).

## Files

| File | What it is |
|------|-----------|
| `schema.sql` | Three tables. **Run once in Supabase Studio → SQL editor.** `crm_prospects` (one row per lead in the positive-reply cadence), `kpi_daily` (one row per day+metric, unique on `(date, metric)`), `content_posts` (one row per published post, primary key `post_id`, powers the Content tab). |
| `supabase_writer.py` | PostgREST CRUD, same auth pattern as `../integrations/instantly/supabase_writer.py`. Prospect list/create/update/delete + KPI get/set/history + `bulk_set_kpi` (chunked upsert for the old-tracker import). Writable-column allowlist on prospect writes. Secret key is server-side only. |
| `__init__.py` | Package marker + module docstring. |

## Data model

**crm_prospects:** `name, company, source, temp (hot|warm), stage (new|contacted|call_booked|showed|won|lost), email, phone, linkedin_url, next_touch_date, last_touch_at, touch_count, notes`.

**kpi_daily:** `date, metric, value`. The dashboard sets absolute values per cell; history accrues for long-term tracking.

## Cadence logic (lives in the front-end)

`crm.html` encodes the locked positive-reply cadence (see [`../../shared/context/sales-and-delivery/positive-reply-cadence.md`](../../shared/context/sales-and-delivery/positive-reply-cadence.md)). "Log touch" bumps `touch_count` and sets `next_touch_date = today + CADENCE[touch_count]`, where `CADENCE = [1,1,1,1,1,2,7,16,30]` (day 0,1,2,3,4,5,7,14,30). Each card surfaces the suggested next action for its touch number.

## Content dashboard (the `/crm` Content tab)

`content_posts` is the deployed mirror of the local tracker CSV
(`tools/social-tracker/posts.csv`). LinkedIn impressions are author-only and
entered by hand via `/social-review`, then pushed up with
`python tools/social-tracker/sync_to_crm.py` → `POST /crm/api/content/import`
(upsert by `post_id`, so re-syncing refreshes metrics, never duplicates). The
Content tab in `crm.html` reads `GET /crm/api/content` and computes everything
client-side, **reach-first** (ranked by impressions): a this-week posting plan
(40/30/20/10 mix across the days), a mix tracker, top posts + best hooks, and
median impressions by post_type / format.

## What does NOT go here

- HTTP routes / the page itself → `../web/crm_routes.py` + `../web/templates/crm.html`
- KPI metric list + targets + cadence intervals → hard-coded in `crm.html` (front-end config), not the DB
- Lead PII must stay in Supabase only, never committed (repo is public). The `/crm` page is protected by the same Traefik basic auth as `/upwork`.
