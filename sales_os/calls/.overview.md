# sales_os/calls — Cold Call Dialer backend

Standalone dialing workspace, **separate from `sales_os/crm`**. Import a US lead CSV, the app parses each phone, sorts it into a calling block by US time zone, and gives Pang one queue to call straight down (from OpenPhone), logging dispositions and scheduling follow-ups. Front-end + routes live in [`../web/dialer_routes.py`](../web/dialer_routes.py) and [`../web/templates/dialer.html`](../web/templates/dialer.html); page is at `/dialer`.

## Files

| File | What it is |
|------|-----------|
| `schema.sql` | Two tables. **Run once in Supabase Studio.** `call_prospects` (one row per lead; phone E.164, area_code, IANA time_zone, calling_block, status, next_follow_up_at, needs_review) + `call_logs` (one row per call attempt, FK to prospect, cascade delete). Partial unique index on `phone` for dedupe. |
| `phones.py` | `BLOCK_MAP` (IANA tz → `morning`/`night`, the one place to retune the schedule) + `parse_phone()` using the `phonenumbers` lib → `{phone, area_code, time_zone, calling_block}` or `None` for unparseable / non-US numbers. |
| `supabase_writer.py` | PostgREST CRUD, same auth pattern as `../crm/supabase_writer.py`. Prospect list (with block/status/due filters, embeds `call_logs`) + create/update/delete + `existing_phones()` + `bulk_insert_prospects()` (import) + `add_log()`. Writable-column allowlist. Secret key server-side only. |

## Calling blocks (Pang is UTC+8)

`morning` = US West (America/Los_Angeles, Denver, Phoenix) — call these first. `night` = US Central + East (Chicago, New_York). Edit `BLOCK_MAP` in `phones.py` to change. Numbers with a US tz outside the map get an empty block; unparseable / non-US numbers are flagged `needs_review`.

## Status / disposition enum (validated in `dialer_routes.py`)

`new, dialed, no_answer, voicemail, not_interested, callback, booked, wrong_number, do_not_call`. A logged call attempt (`/log`) also advances the prospect's `status`.

## What does NOT go here

- HTTP routes / the page → `../web/dialer_routes.py` + `../web/templates/dialer.html`
- Anything touching `crm_*` tables — this module is deliberately separate
- Lead PII stays in Supabase only (repo is public); `/dialer` is behind the same Traefik basic auth as `/crm`.
