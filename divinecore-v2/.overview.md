# divinecore-v2 — Code-First Runtime

Parallel track to n8n orchestration. This folder is the **runtime only** — FastAPI API, Celery worker, Celery Beat scheduler, Redis broker, Docker Compose. Domain code (Upwork, Fathom, Instantly, etc.) lives in module folders (`sales_os/`, `ops_os/`) and is imported by the runtime at build time.

## Architecture

**Stack:** FastAPI API + Celery worker + Celery Beat scheduler + Redis broker, all in Docker Compose.

```
divinecore-v2/
├── api/
│   ├── main.py        — health check + /tasks routes; imports + mounts routers from <module>/web/
│   ├── settings.py    — Pydantic Settings (REDIS_URL)
│   ├── requirements.txt
│   └── Dockerfile     — context = repo root; copies api/ + sales_os/
├── worker/
│   ├── celery_app.py  — Celery config + beat_schedule + include=[...] task paths
│   ├── tasks.py       — echo, heartbeat (generic infra tasks)
│   ├── settings.py    — Pydantic Settings (Supabase, OpenRouter, Fathom, Google OAuth, Redis)
│   ├── team.py        — TEAM_MEMBERS dict + email/name lookup
│   ├── requirements.txt
│   └── Dockerfile     — context = repo root; copies worker/ + sales_os/ + ops_os/
├── docker-compose.yml         — local dev: context: .., volume mounts, hot-reload
└── docker-compose.prod.yml    — VPS deploy: images from GHCR, restart: unless-stopped, Traefik auth
```

Domain code (mounted into containers from outside divinecore-v2/):
- `sales_os/integrations/upwork/` — Upwork proposal generation (Celery tasks)
- `sales_os/web/upwork_routes.py` — `/upwork` form and results UI
- `ops_os/integrations/fathom/` — Fathom recording poller (Celery tasks)

Services in compose:
- `redis` — broker, 6379
- `api` — FastAPI on :8000, connects to Celery via REDIS_URL
- `worker` — Celery worker, processes tasks
- `beat` — Celery Beat scheduler, runs periodic tasks (heartbeat every 30s)

## Endpoints

- `GET /` — health
- `POST /tasks/echo` — submit task, returns task_id
- `GET /tasks/{task_id}` — poll status + result
- `GET /upwork` — proposal generator form. **Public:** https://upwork.srv1445995.hstgr.cloud/upwork (basic auth)
- `POST /upwork` — runs proposal pipeline (2 LLM calls + Google Docs/Drive/Sheets), returns generated copy + Doc URL
- `POST /upwork/finalize` — patches connects + Loom URL into tracking sheet
- `GET /upwork-jobs` — manual review queue from Apify daily scrape (basicauth)
- `GET /upwork-jobs/{job_id}` — single job detail + action buttons
- `POST /upwork-jobs/{id}/{action}` — skip, unskip, or unmark applied
- `POST /upwork-jobs/{id}/generate` — generate proposal from stored job description
- `POST /instantly/webhook` — inbound reply processor (public, webhook-secret validated)
- `GET /outreach` — Instantly campaign reporting dashboard (basicauth)
- `GET /crm` — Leads CRM + KPI dashboard, single-page app (basicauth). JSON API under `/crm/api/*` (prospects CRUD, KPI get/set/history). Supabase-backed (`crm_prospects`, `kpi_daily`). Code in `sales_os/crm/` + `sales_os/web/crm_routes.py`. Run `sales_os/crm/schema.sql` in Supabase once before first use.

## Integrations

**Fathom** — Beat polls Fathom REST API every 10 min, upserts new meetings to Supabase `meetings` table, creates Pulse task rows. Outbound only. Lives in `ops_os/integrations/fathom/`. See `ops_os/integrations/fathom/.overview.md`.

**Upwork** — User-initiated via `/upwork` form. Pipeline: 2 OpenRouter LLM calls (proposal fields, application copy) + Google Docs/Drive/Sheets (template copy, mail-merge, share, append to sheet). Lives in `sales_os/integrations/upwork/`. Env vars: `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, `GOOGLE_OAUTH_REFRESH_TOKEN`. See `sales_os/integrations/upwork/.overview.md`.

**Instantly** — Cold-email outreach engine. Webhook at `POST /instantly/webhook` validates secret header, stores meaningful replies to Supabase + Discord. Daily beat task snapshots campaign analytics. Dashboard at `GET /outreach`. Lives in `sales_os/integrations/instantly/`. Env vars: `INSTANTLY_API_KEY`, `INSTANTLY_WEBHOOK_SECRET`, `DISCORD_OUTREACH_WEBHOOK_URL`, `DISCORD_OUTREACH_THREAD_ID`. See `sales_os/integrations/instantly/.overview.md`.

**Upwork jobs feed (Apify)** — Daily Apify scrape of a saved-search URL at 21:40 UTC (05:40 MYT). Upserts to Supabase `upwork_jobs` table. Pang reviews queue manually at `/upwork-jobs`, generates proposals on-demand. Operator-owned columns (status, applied_at, proposal_doc_url) persist across daily re-fetches via PostgREST column filters. Cost: ~$3-10/mo at one-run-per-day volume. Lives in `sales_os/integrations/upwork_jobs/`. Env vars: `APIFY_API_TOKEN`, `UPWORK_SEARCH_URL`. See `sales_os/integrations/upwork_jobs/.overview.md`.

## CI/CD

**File:** `.github/workflows/divinecore-v2-ci.yml`

**Triggers:** push/PR to main (path-filtered to `divinecore-v2/**`, `sales_os/**`, `ops_os/**`) + `workflow_dispatch`.

**Build & push job** (matrix: `api`, `worker`):
- Runs both components in parallel
- Build context = repo root; Dockerfile paths are `divinecore-v2/{api,worker}/Dockerfile`
- Uses buildx + build-push actions
- Pushes to `ghcr.io/divineside/aios-divinecore/{api,worker}` (upstream org)
- Tags: `:latest` (main only), `:sha-<short>`, `:<branch>`
- GHA cache scoped per component
- PRs: build-only (no push, no Discord ping)

**Notify job:** Runs after build-and-push on push + dispatch (not PRs). Posts status to `#deploys` Discord via webhook.

**Secrets required:**
- `GITHUB_TOKEN` — auto-provisioned, used for GHCR auth
- `DISCORD_WEBHOOK_URL` — webhook for `#deploys` channel

**Permissions:** `contents: read`, `packages: write`.

## Deployment (VPS)

**Location:** `/root/divinecore-v2/` on Hostinger VPS (srv1445995.hstgr.cloud), deployed 2026-05-03.

**Running services:**
- `divinecore-v2-redis-1` — internal compose network only
- `divinecore-v2-api-1` — FastAPI on port 8000; attached to `divinecore` bridge + `n8n_default` (for Traefik)
- `divinecore-v2-worker-1` — Celery worker, connected to Redis
- `divinecore-v2-beat-1` — Celery Beat, running scheduled tasks

All four have `restart: unless-stopped`. Isolated from n8n containers via dedicated `divinecore` bridge (api additionally joins `n8n_default` for discovery).

**GHCR auth:** `docker login ghcr.io` with GitHub PAT (`read:packages` scope). Credentials cached in `/root/.docker/config.json`. Rotate PAT on expiration.

**Manual deploy:**
```
ssh root@srv1445995.hstgr.cloud "cd /root/divinecore-v2 && docker compose pull && docker compose up -d"
```

**Smoke test:** `POST /tasks/echo` → Redis queue → worker process → `GET /tasks/{id}` returns SUCCESS. Full async pipeline verified end-to-end.

## Public endpoints & TLS

**`/upwork` live at:** https://upwork.srv1445995.hstgr.cloud/upwork (deployed 2026-05-04). Routed through n8n's Traefik (the only reverse proxy on VPS).

**Wiring:**
- api service in `docker-compose.prod.yml` carries `traefik.*` labels (Host rule, websecure, tls=true, basicauth middleware)
- api attached to external `n8n_default` network for Traefik discovery
- Basic auth via inline bcrypt hash in label (double dollar signs per compose syntax)
- **TLS is self-signed** (Traefik default). Browser shows one-time warning per device; click through. Reason: Let's Encrypt rate-limited `*.hstgr.cloud` apex. To upgrade: migrate to domain outside the apex (~$1–12/yr) or wait for quota rollover.

**n8n global:** HTTP to HTTPS redirect on Traefik command line. Shared with n8n; audit before changing.
