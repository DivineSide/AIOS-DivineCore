# tools/social-tracker/

Manual, no-scraper LinkedIn + X post tracker. You log each post the moment you
publish it, fill in the metrics once a week, and the tool surfaces which post
type / format / topic / hook actually performs — so content decisions run off
your own data instead of vibes.

Built this way deliberately: scraping personal-post analytics is unreliable
(LinkedIn impressions are author-only and can't be scraped at all; X views are
public but actor IDs/pricing churn) and needs a paid Apify plan. Manual logging
sidesteps all of it and follows the repo's "manual first, automate second" rule.
If volume ever justifies it, the CSV mirrors the `social_posts` Supabase schema,
so it can be bulk-loaded into the automated `/social-perf` dashboard later.

## How it splits the work

- **The LLM classifies** (in the `/log-post` command) — the part only a model
  can do: read the post, tag it against the playbook taxonomy.
- **Python owns storage + stats** (`social_log.py`) — deterministic: write a
  well-quoted row, update metrics, compute the leaderboard / bucket stats /
  actual-vs-target mix. Mirrors the social_perf annotator-vs-code split.

## Files

| File | Role |
|------|------|
| `social_log.py` | CLI: `add` / `set-metrics` / `pending` / `report`. Owns `posts.csv`. |
| `posts.csv` | The data. **Gitignored** — LinkedIn impressions are private analytics and this repo is public. Created on first `add`. |
| `.inbox.txt` | Scratch file the `/log-post` command writes the raw post body into before calling `add --content-file` (robust multiline handling). Gitignored. |

## The two commands

- **`/log-post <paste>`** — classify one post + append a row (metrics blank).
- **`/social-review`** — weekly: fill metrics for pending posts, then report +
  interpret what's working.

## Taxonomy (source of truth: linkedin-playbook.md)

- `post_type`: authority / educational / personal / social-proof — §12.1, also
  the basis for the 40/30/20/10 actual-vs-target mix.
- `framework`: PAS / SLA / case-study / BAB — §07.
- `funnel_stage`: top / middle / bottom.
- `format`: list / story / insight / question / case-study / hot-take /
  tutorial / announcement / other — matches the social_perf annotator enum.
- `differentiator`: which §01 distinction the post drew (or `none`, which the
  command flags).
- plus verbatim `hook` + `closing`, free-text `topic`, and the metric columns.

## What it does NOT do

- No scraping, no API calls, no LLM calls of its own (the command does the LLM
  part). Pure local CSV + stdlib.
- No true conversion tracking (post → DM → call). Engagement is the proxy;
  standout posts get flagged in `notes` for manual conversion checks.
- X has no locked target mix yet — `report` shows X distribution without a
  target. Set one in `TARGET_MIX` / x-playbook when it's decided.
