# This .md file contain my comments on "pang-on-review-system.md".

## We don't need to track payments, the reason why pang included it, is because he assumes we need to track payment transaction occured as a trigger point for the review system. It's not true because most business take payment before the course starts - so sending a review request before the service is spam and even if the transaction happens later we have other ways to solve it - this is the question we have to ask the business owner, how they currently track a students course duration? (this will be the trigger, course ends - fire request).

## On the website widget or a review social post widget, Go High Level does provide a website builder, but we are not building a website for them. Go High Level builds websites, and they provide widgets straight to be plugged in inside their website, to put it in their website, we will need access to their codebase (wherever their code lives).  Creating a widget is not that tough, so it's not really a problem. What would be a problem is access to their website code so that we can directly plug in the review widget on their website.
